Forge v2 Engineering & Design Specification

====================================================
PROJECT
====================================================

Project Name: Forge

Forge is a premium offline-first Android fitness tracker built entirely in Flutter.

The goal is to create the highest quality offline gym tracker possible with a beautiful Apple-inspired glassmorphic interface while following Flutter best practices and clean architecture.

Everything must be production-ready.

====================================================
CORE PRINCIPLES
====================================================

• 100% Offline First
• No Firebase
• No Login
• No Internet Required
• Android First
• Feature-first Architecture
• Modular
• Scalable
• Maintainable
• Production Ready
• Material 3
• Apple-inspired UI
• VisionOS-inspired glass effects
• 60 FPS animations
• Accessibility built-in
• Zero hardcoded spacing
• Zero hardcoded colors
• Design Token System
• Reusable UI Components
• Consistent Animations
• Clean Architecture
• SOLID Principles
• Riverpod only
• Hive only

====================================================
CODE QUALITY RULES
====================================================

Never use

setState() for application state

Global variables

Business logic inside widgets

God classes

Widgets larger than ~250 lines

Duplicate code

Magic numbers

Magic strings

Deprecated APIs

Default Material Cards

Default AlertDialogs

Default BottomNavigationBar

Default FloatingActionButton

Default BottomSheets

Default SnackBars

Instead use reusable Forge components.

====================================================
RULE FOR EVERY FUTURE PROMPT
====================================================

Every generated feature must

• Use only Forge Design System components.
• Follow the feature-first architecture.
• Never introduce duplicate code.
• Never use default Material widgets when a Forge component exists.
• Compile with zero warnings.
• Pass flutter analyze.
• Pass flutter test.
• Be production-ready before moving to the next phase.
